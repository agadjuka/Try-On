Готовность к Oracle Cloud
Проект почти готов к деплою на Oracle VM, и я уже добавил/адаптировал необходимые infra-файлы в репозитории:
обновлен Dockerfile (убрана жесткая cloud-run привязка к порту, добавлен APP_PORT)
создан docker-compose.yml (restart: always, env_file, порты, volume для GCP key)
создан .github/workflows/deploy.yml (SSH деплой через GitHub Actions)
добавлен .env.example (шаблон переменных окружения)
1) Архитектура запуска: Webhook vs Long Polling
Сейчас основной прод-запуск — Webhook:
Dockerfile запускает uvicorn main:app
main.py содержит endpoint POST /telegram/webhook
В проекте также есть Long Polling режим (run_bot.py), но он сейчас не является default для контейнера.
Что выбрать на Oracle VM
Если нужен REST API для сайта (а у вас он есть в main.py): оставлять Webhook/FastAPI логично.
Если нужен только бот и не нужен входящий HTTP: можно перейти на polling (python run_bot.py) и закрыть входящие порты.
Порт и PORT
Приложение слушает порт 8080 по умолчанию.
Жесткой зависимости от Cloud Run переменной PORT в коде не найдено.
Я адаптировал Dockerfile на переменную APP_PORT (дефолт 8080), чтобы на VM порт задавался явно через .env.
2) Docker-состояние
Dockerfile корректный для Python/FastAPI и теперь подходит для IaaS.
ENTRYPOINT/CMD: теперь CMD запускает uvicorn через APP_PORT.
Добавлен docker-compose.yml с:
сборкой из Dockerfile
restart: always
env_file: .env
ports
volume для GCP service account json
3) State / Storage
Локального персистентного state (sqlite/json-хранилища) в runtime-логике не обнаружено.
Основное состояние хранится во внешних сервисах:
Firestore
Google Cloud Storage
Логи пишутся в stdout (через loguru), что хорошо для контейнеров.
В docker-compose.yml добавлен volume bot_data как резерв; критичного локального state сейчас нет.
4) Переменные окружения
Обязательные/используемые переменные:
BOT_TOKEN
GOOGLE_CLOUD_PROJECT_ID
GOOGLE_CLOUD_REGION
GCS_BUCKET_NAME
FIRESTORE_DATABASE_ID (если не задано — fallback (default))
TELEGRAM_ADMIN_GROUP_ID (опционально, для админ-панели)
ADMIN_PANEL_FORWARDING_ENABLED
APP_PORT (для VM, дефолт 8080)
GOOGLE_APPLICATION_CREDENTIALS (задается в compose как путь внутри контейнера)
Как передавать в Docker
На сервере хранить .env в /home/ubuntu/bot_project/.env.
В docker-compose.yml уже настроено env_file: .env.
Ключ GCP хранить на сервере как /home/ubuntu/bot_project/secrets/gcp-sa.json, он монтируется в контейнер.
5) CI/CD GitHub Actions
Сделан workflow push -> main -> ssh -> git pull -> docker compose up -d --build.
Секреты используются:
SERVER_IP
SERVER_USER
SERVER_SSH_KEY
Что нужно изменить прямо сейчас (критично)
Удалить реальные секреты из репозитория и ротировать токены:
у вас в .env уже лежат реальные значения (включая BOT_TOKEN), это риск компрометации.
Убедиться, что на сервере есть:
/home/ubuntu/bot_project/.env
/home/ubuntu/bot_project/secrets/gcp-sa.json
Если оставляете webhook:
открыть порт (APP_PORT, обычно 8080) в Oracle Security List/NSG
обеспечить HTTPS-домен/прокси (Telegram webhook требует публичный HTTPS endpoint)

Полное содержимое docker-compose.yml
services:
  bot:
    container_name: vyon-bot
    build:
      context: .
      dockerfile: Dockerfile
    restart: always
    env_file:
      - .env
    environment:
      APP_PORT: ${APP_PORT:-8080}
      GOOGLE_APPLICATION_CREDENTIALS: /run/secrets/gcp-sa.json
    ports:
      - "${APP_PORT:-8080}:8080"
    volumes:
      # Service account JSON должен находиться на сервере в ./secrets/gcp-sa.json
      - ./secrets/gcp-sa.json:/run/secrets/gcp-sa.json:ro
      # Резерв под возможные локальные артефакты/кэш
      - bot_data:/code/data
volumes:
  bot_data:
Полное содержимое .github/workflows/deploy.yml
name: Deploy to Oracle VM
on:
  push:
    branches:
      - main
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1.2.0
        with:
          host: ${{ secrets.SERVER_IP }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script_stop: true
          script: |
            set -e
            cd /home/ubuntu/bot_project
            git fetch --all
            git checkout main
            git pull origin main
            docker compose down
            docker compose up -d --build
            docker image prune -f
